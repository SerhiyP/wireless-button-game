# Бездротова Система Кнопок для Ігор

Система складається з одного приймача (дисплей) та до 12 передавачів (кнопок). Кожна кнопка налаштовується унікальним номером гравця (`BUTTON_ID`, 0–11) перед завантаженням одного й того самого скетча.

## 📋 Опис Проекту

Це система для змагальних ігор, де гравці натискають свої кнопки, а перший, хто натисне, виграє. Номер переможця показується на 2-значному 7-сегментному дисплеї приймача. Система використовує бездротовий зв'язок nRF24L01 для передачі сигналів між кнопками та дисплеєм.

### Особливості:
- ✅ Бездротовий зв'язок nRF24L01 (за замовчуванням `RF24_PA_LOW`, ~10м; можна змінити на `RF24_PA_HIGH`, ~100м)
- ✅ До 12 гравців, кожен з унікальним `BUTTON_ID` (0–11)
- ✅ 13-адресна система комунікації (`00001` — дисплей, `00002`–`00013` — кнопки)
- ✅ Переможець показується номером на 7-сегментному дисплеї + світлодіодом на власній кнопці
- ✅ Одноразове натискання (one-shot) — кнопка блокується після першої спроби передачі, аж до `GAME_RESET`
- ✅ Початковий стан готовності (запобігає передчасним натисканням)
- ✅ Автоматичне скидання гри через кнопку на дисплеї
- ✅ Самоперевірка 7-сегментного дисплея при старті
- ✅ Автоматичне підключення кнопок до дисплея в будь-якому порядку ввімкнення (пінг)
- ✅ Двостороння комунікація між пристроями
- ✅ 3 світлових індикатори стану на кожній кнопці (переможець, готовність, з'єднання)
- ✅ Повна діагностика через Serial Monitor (9600 baud)

## 🔧 Необхідні Компоненти

### Для кожного пристрою:
- 1x Arduino Uno/Nano/Pro Mini
- 1x nRF24L01 модуль
- Джерело живлення (батарейки або USB)
- 1x Конденсатор 10–100 мкФ (між VCC/GND модуля nRF24L01 — див. примітку про стабільність нижче)

### Для кожної кнопки (до 12 шт.):
- 1x Кнопка (тактова)
- 3x Світлодіоди (переможець, готовність, з'єднання)
- 3x Резистор 220Ω (для світлодіодів)
- Дроти для підключення

### Для приймача (дисплей):
- 1x Кнопка скидання
- 1x 2-значний 7-сегментний індикатор (керується через 2x 74HC595 зсувний регістр)
- Дроти для підключення

## 🔌 Схема Підключення

### Кнопки (button/button.ino):
```
Arduino Pin  →  Компонент
Pin 2        →  Кнопка (другий контакт до GND)
Pin 3        →  Світлодіод готовності (+ через резистор 220Ω)
Pin 4        →  Світлодіод переможця (+ через резистор 220Ω)
Pin 5        →  Світлодіод з'єднання (+ через резистор 220Ω)
Pin 9        →  nRF24L01 CE
Pin 10       →  nRF24L01 CSN
Pin 11       →  nRF24L01 MOSI
Pin 12       →  nRF24L01 MISO
Pin 13       →  nRF24L01 SCK
3.3V         →  nRF24L01 VCC
GND          →  nRF24L01 GND
```

### Приймач (display/display.ino):
```
Arduino Pin  →  Компонент
Pin 4        →  DS (Data) — 74HC595 (7-сегментний індикатор)
Pin 5        →  SH_CP (Clock) — 74HC595
Pin 6        →  Кнопка скидання (другий контакт до GND)
Pin 7        →  ST_CP (Latch) — 74HC595
Pin 9        →  nRF24L01 CE
Pin 10       →  nRF24L01 CSN
Pin 11       →  nRF24L01 MOSI
Pin 12       →  nRF24L01 MISO
Pin 13       →  nRF24L01 SCK
3.3V         →  nRF24L01 VCC
GND          →  nRF24L01 GND
```

> ⚠️ Якщо цифри на індикаторі виглядають переставленими місцями/дзеркальними, поміняйте місцями два виклики `shiftOut()` у функції `writeDigits()` в `display.ino`.

> 💡 **Порада для стабільності:** припаяйте конденсатор 10–100 мкФ між VCC та GND модуля nRF24L01, якомога ближче до самого модуля (на обох типах пристроїв). Бортовий стабілізатор 3.3В на платах Uno/Nano-класу розрахований на невеликий постійний струм і часто не встигає віддати стрибок струму, який модуль споживає під час передачі (TX). Це просідання напруги — типова причина нестабільних помилок `radio.begin()`/`radio.write()`, навіть коли живлення взагалі підключене правильно (3.3V, а не 5V).

## 📥 Встановлення

### 1. Підготовка Arduino IDE:
```
1. Встановіть бібліотеку RF24:
   Sketch → Include Library → Manage Libraries → Пошук "RF24" → Install

2. Підключіть Arduino до комп'ютера
```

### 2. Завантаження коду:
```
1. Відкрийте 'button/button.ino'. У секції конфігурації встановіть BUTTON_ID —
   унікальний номер цієї кнопки (0–11). Кожна фізична кнопка повинна мати свій
   номер, інакше дві кнопки конфліктуватимуть на одній радіоадресі.
2. Завантажте налаштований скетч на кожен пристрій-кнопку.
3. Відкрийте 'display/display.ino'. За потреби змініть NUM_PLAYERS (кількість
   гравців, за замовчуванням 12) → завантажте на Arduino-приймач.
```

### 3. Перевірка роботи:
```
1. Відкрийте Serial Monitor (Ctrl+Shift+M)
2. Встановіть швидкість 9600 baud
3. Перезапустіть Arduino - дисплей виконає самоперевірку (перебір 00-99,
   потім риски), кнопки почнуть пінгувати дисплей до отримання відповіді
```

## 🎮 Використання

### Запуск гри:
1. **Увімкніть дисплей та всі кнопки** (у будь-якому порядку — кнопки самі знайдуть дисплей)
2. **Дисплей виконає самоперевірку** — кнопки самі підключаться протягом ~1 секунди,
   надсилаючи `PING_<номер>`, у відповідь на який дисплей надішле `SYSTEM_READY`.
   Порядок ввімкнення пристроїв не має значення
3. **Натисніть кнопку скидання на дисплеї** — почнеться гра, дисплей покаже риски `--`
4. **Гравці натискають свої кнопки** — перший виграє!

### Індикатори:

#### Кнопки:
**Світлодіод готовності (Pin 3):**
- **Блимає повільно** - немає зв'язку з дисплеєм (кнопка пінгує його щосекунди)
- **Горить** - система готова, можна натискати кнопку
- **Блимає швидко** - переможець (отримано підтвердження `WIN_<номер>`)

**Світлодіод переможця (Pin 4):**
- **Вимкнений** - кнопка не натиснута або програла
- **Горить** - ця кнопка виграла (отримано підтвердження)

**Світлодіод з'єднання (Pin 5):**
- **Блимає під час ініціалізації** - налаштування радіо
- **Горить** - радіо працює нормально
- **Миготить** - передача/прийом даних

#### Дисплей (7-сегментний індикатор):
- **Перебір 00→99, потім риски, потім порожньо** - самоперевірка при старті
- **`--` (риски)** - система готова / гра активна, очікуємо натискання
- **Число (00–11)** - номер гравця, який виграв
- **`E1`** - помилка ініціалізації радіо

> Повідомлення, які не є коректним номером гравця (пошкоджений пакет або чужий передавач
> на тому ж каналі/адресі), відхиляються без жодної реакції на індикаторі — їх видно лише
> в Serial Monitor як `Declined: <вміст>`. Раніше на них показувався код `E2` із затримкою
> 500 мс, під час якої дисплей не чув натискань, і випадковий пакет міг коштувати гравцю
> раунду.

## 🔍 Налагодження

### Відкрийте Serial Monitor для діагностики:

#### Нормальні повідомлення кнопки:
```
Button 0 Transmitter Starting...
Radio initialized, pinging display until it answers...
Ping delivered, waiting for SYSTEM_READY...
SYSTEM_READY received!
Button 0 Ready!
Sending 0 signal...
0 signal sent successfully!
WIN_0 received! This button won!
GAME_RESET received! Ready for new game.
```

#### Нормальні повідомлення дисплея:
```
Display Unit Starting...
Running display self-test...
Display Unit Ready! Press reset to start game.
Message sent to 00002: SYSTEM_READY
=== NEW GAME STARTED! ===
Press any button!
Received: 0
Message sent to a button: WIN_0
Player 0 WINS!
```

### Поширені проблеми:

#### ❌ "Radio initialization failed!"
**Причина:** Проблема з підключенням чи живленням nRF24L01
**Рішення:**
- Перевірте всі з'єднання
- Переконайтеся, що nRF24L01 підключений до 3.3V (НЕ 5V!)
- Додайте конденсатор 10–100 мкФ між VCC/GND модуля — часта причина нестабільної ініціалізації навіть при правильній напрузі
- Спробуйте інший nRF24L01 модуль

#### ❌ "No answer from display, retrying..."
**Причина:** Дисплей не підтверджує пінг кнопки — зв'язку немає
**Рішення:**
- Перевірте, чи увімкнений дисплей (світлодіод готовності кнопки блиматиме, доки зв'язку немає)
- Зменшіть відстань між пристроями
- Перевірте адреси: дисплей = `"00001"`, кнопки = `"00002"`..`"00013"` (адреса = `BUTTON_ID + 2`)
- Кнопка повторює пінг щосекунди й підключиться сама, щойно дисплей з'явиться —
  перезавантажувати її не потрібно

#### ❌ "Ping delivered, waiting for SYSTEM_READY..." повторюється
**Причина:** Радіо дисплея відповідає (auto-ACK), але сам дисплей не надсилає відповіді
**Рішення:**
- Норма, якщо зараз триває раунд: підключення дозволене лише між раундами. Натисніть
  кнопку скидання на дисплеї — `GAME_RESET` приєднає кнопку
- Якщо раунд не триває, у Serial Monitor дисплея має бути `Ping from player <n> - deferred`
  або `Message sent to ...: SYSTEM_READY`. Якщо немає жодного — головний цикл дисплея завис,
  перезавантажте його

#### ❌ Кнопки не реагують
**Причина:** Гра не запущена або система не готова
**Рішення:**
- Натисніть кнопку скидання на дисплеї
- Перевірте Serial Monitor дисплея
- Переконайтеся, що кнопки підключилися (`Button <n> Ready!` у їхньому Serial Monitor,
  або `Ping from player <n>` у Serial Monitor дисплея)

#### ❌ "Failed to send signal!"
**Причина:** Проблема передачі
**Рішення:**
- Перевірте відстань між пристроями
- Перевірте живлення nRF24L01 (3.3V + конденсатор 10–100мкФ для стабільності)
- Перевірте антени модулів
- Перевірте правильність адрес у коді

#### ❌ На дисплеї показується неправильний номер переможця
**Причина:** Дві кнопки мають однаковий `BUTTON_ID` (конфлікт радіоадреси)
**Рішення:**
- Перевірте, що кожна фізична кнопка має унікальний `BUTTON_ID` (0–11) перед завантаженням
- Перезавантажте всі пристрої з правильними ID

#### ❌ Система не скидається після гри
**Причина:** `GAME_RESET` не доходить до кнопок
**Рішення:**
- Перевірте Serial Monitor дисплея на повідомлення про відправку
- Зменшіть відстань між пристроями
- Натисніть reset кілька разів

## ⚙️ Технічні Деталі

### Логіка роботи:

#### Кнопки:
1. **Ініціалізація** - налаштування радіо (адреса = `BUTTON_ID + 2`)
2. **Пошук дисплея** - кнопка щосекунди надсилає `PING_<BUTTON_ID>` на адресу дисплея,
   доки не отримає у відповідь `SYSTEM_READY`. Апаратний auto-ACK nRF24 (успішний
   `radio.write()`) для цього НЕ достатній: він підтверджує лише те, що радіомодуль
   дисплея увімкнений, бо генерується самою мікросхемою без участі процесора. Тому
   готовність дає саме повідомлення-відповідь, яке може надіслати лише робочий
   головний цикл дисплея
3. **Готовність** - кнопка активна після отримання `SYSTEM_READY` (у відповідь на пінг
   або разом із `GAME_RESET` на початку нового раунду)
4. **Дебаунсинг кнопки** - запобігає множинним спрацьовуванням (50мс)
5. **Відправка сигналу** - одноразова передача номера гравця (one-shot: прапорець `sent` блокує повторні спроби до `GAME_RESET`)
6. **Очікування підтвердження** - чекає `WIN_<BUTTON_ID>` від дисплея
7. **Індикація переможця** - LED на кнопці світиться тільки якщо отримано підтвердження
8. **Скидання** - лише за сигналом `GAME_RESET` від дисплея (автоматичного скидання за часом немає)

#### Дисплей:
1. **Ініціалізація** - самоперевірка 7-сегментного індикатора та налаштування радіо. Розсилки при старті немає: кнопки знаходять дисплей самі, тож порядок ввімкнення не важливий
2. **Централізована конфігурація** - `NUM_PLAYERS` визначає кількість підтримуваних кнопок; адреси й win-повідомлення обчислюються з номера гравця (`addrFor`/`winMsgFor`)
3. **Обробка пінгів** - `PING_<n>` розпізнається за префіксом і не вважається натисканням.
   Дисплей відповідає `SYSTEM_READY` лише між раундами: під час активного раунду він
   перейшов би на передачу й на кілька мілісекунд оглух би до натискань, а натискання,
   що не отримало auto-ACK, блокується прапорцем `sent` до кінця раунду. Кнопка, що
   ввімкнулася посеред раунду, продовжує пінгувати й приєднається на наступному
   `GAME_RESET`
4. **Стан готовності** - показує риски `--`, доки не почнеться гра
5. **Активна гра** - приймає сигнали від кнопок, показує риски до першого натискання
6. **Визначення переможця** - перший отриманий коректний номер (`0`..`NUM_PLAYERS - 1`) виграє й показується на індикаторі
7. **Підтвердження переможця** - відправка `WIN_<n>` назад на адресу переможця

### Налаштування:

#### Зміна дальності передачі:
```cpp
// У setup() функції змініть:
radio.setPALevel(RF24_PA_LOW);    // Мала потужність (~10м, за замовчуванням)
radio.setPALevel(RF24_PA_HIGH);   // Висока потужність (~100м)
```

#### Зміна кількості гравців:
```cpp
// У display.ino змініть:
const int NUM_PLAYERS = 12;  // підтримувані гравці: 0..(NUM_PLAYERS - 1)
```
> Кожна кнопка також повинна мати унікальний `BUTTON_ID` у діапазоні `0..(NUM_PLAYERS - 1)`.

#### Зміна швидкості дебаунсингу:
```cpp
// У button.ino змініть затримку дебаунсингу:
unsigned long debounceDelay = 50;   // 50мс (стандарт)
unsigned long debounceDelay = 100;  // 100мс (повільніше)
```

## 📊 Характеристики

- **Дальність:** до 10 метрів (`RF24_PA_LOW`, за замовчуванням) або до 100 метрів (`RF24_PA_HIGH`)
- **Кількість гравців:** до 12 (`NUM_PLAYERS`)
- **Живлення nRF24L01:** строго 3.3V (НЕ 5V!)
- **Живлення Arduino:** 5–12V (залежно від плати)
